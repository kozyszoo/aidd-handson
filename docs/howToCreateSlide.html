「資料作成」は最も時間を奪われる作業のひとつです。AI コーディングエージェントを使えば、 テキストの箇条書きから、見栄えの整ったプレゼンスライドまでを丸ごと自動生成できます。 さらに本ハンズオンの目玉は、AI が 生成したスライドを実際にブラウザで開いてスクリーンショットを撮り、 文字のはみ出し・余白・コントラストを自分で確認して直す「自律的デザインチェック」です。

📊 スライド3形式の比較

基礎知識

まずは 3 つのフォーマットの性格を押さえましょう。「迷ったら Slidev」が無難ですが、用途次第です。

項目 Slidev Marp HTML（自作）
記述方法 Markdown + Vue Markdown のみ HTML / CSS / JS
学習コスト 中 低（最も簡単） 高（自由度の代償）
デザイン自由度 高（Vue / UnoCSS［Tailwind互換］/ コンポーネント） 中（テーマ CSS） 最高（何でもできる）
コードハイライト ◎ 標準で美しい ◯ △ 自前で用意
アニメーション ◎ クリック送り対応 △ 限定的 ◯ JS 次第
PDF 書き出し slidev export marp --pdf Playwright / 印刷
向いている人 エンジニア登壇・技術発表 とにかく速く・GitHub 管理 ブランド固有の凝った1枚物

📝 Markdown 系（Slidev / Marp）の利点

  • テキスト主体なので AI が生成・修正しやすい
  • 差分がきれいで Git 管理に強い
  • テーマを変えるだけで一括で見た目が変わる

🎨 HTML 系の利点

  • レイアウトの自由度が無限大
  • 独自フォント・アニメ・SVG を盛り込める
  • このポータル資料のような独自世界観を作れる
💡 ハンズオンの進め方
時間が限られる場合は Step 4（Slidev）だけを実習し、Marp・HTML は読み物として眺めるのがおすすめです。 3 形式すべてを試すと、自分の好みがはっきり分かります。

⚙️ Step 1: 環境構築

⏱ 10分

1-1. 作業フォルダを用意

# スライド用の作業フォルダを作成
mkdir ai-slides && cd ai-slides

# Git 管理を開始（任意だが推奨）
git init

1-2. Node.js の確認

# Node.js 22.12.0 以上の、サポート中の LTS 版が必要
node --version
npm --version
⚠️ Node.js が古い / 入っていない場合
nodejs.org から LTS 版をインストールするか、 nvm（Node Version Manager）でバージョンを切り替えてください。

1-3. ツールのインストール（後の Step で使う分）

各形式で必要なツールは、後ほど AI に入れてもらってもOKですが、先に把握しておきましょう。

# Slidev（プロジェクト作成時に自動セットアップ）
npm init slidev@latest

# Marp CLI（グローバル不要、npx で都度実行）
npx @marp-team/marp-cli@latest --version

# Playwright（スクショ用ブラウザ）
npx playwright install chromium
✅ チェックポイント
node --version で Node.js 22.12.0 以上の、サポート中の LTS 版であることを確認し、作業フォルダで git status が動けば Step 1 完了です。

🎭 Step 2: Playwright MCP / CLI のセットアップ

⏱ 10分

Playwright はブラウザを自動操作するツールです。これを AI に渡すことで、AI が 「スライドをブラウザで開いて、スクリーンショットを撮る」ことができるようになります。 使い方は大きく MCP 経由と CLI 経由の 2 通りです。

2-1. 方法A: Playwright MCP（推奨）

MCP方式では、事前に Google Chrome をインストールしてください。

MCP（Model Context Protocol）でブラウザ操作機能を AI に「ツール」として渡す方法です。AI が能動的にブラウザを操作できます。

Claude Code

# Playwright MCP を追加
claude mcp add playwright -- npx @playwright/mcp@latest

# 追加されたか確認
claude mcp list

Codex / Antigravity

Codex は端末で codex mcp add playwright -- npx -y @playwright/mcp@latest を実行し、codex mcp list で確認します。下の JSON 例は Antigravity 用です。Codex の config.toml には貼り付けません。

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}
📍 設定ファイルの場所
Antigravity 2.0 は Settings → Customizations → Installed MCP Servers。Antigravity IDE で上の JSON を登録する場合は、エージェントパネル上部の … → MCP Servers → Manage MCP Servers → View raw config を開き、既存の設定に playwright を追加します。 詳細は Codex ガイド / Antigravity ガイド の MCP セクションを参照してください。

2-2. 方法B: Playwright CLI / スクリプト

MCP が使えない環境では、AI に「スクショ用の小さなスクリプトを書いて実行させる」方法が確実です。AI が以下のようなファイルを生成し、自分で実行します。

// shot.mjs — 指定 URL を開いてスクショを保存する
import { chromium } from 'playwright';

const browser = await chromium.launch();
const page = await browser.newPage({
  viewport: { width: 1280, height: 720 } // スライドは 16:9
});
await page.goto('https://example.com');   // ブラウザ起動と撮影の確認用
await page.screenshot({ path: 'slide-1.png' });
await browser.close();

Step 4 で Slidev を起動した後は、起動時に表示された URL に変えます。

# 実行（playwright をローカルに入れてから）
npm install -D playwright
node shot.mjs
# → slide-1.png が生成され、これを AI に読ませる

2-3. どちらを使う？

✅ MCP が向くケース

  • AI に主体的にブラウザ操作させたい
  • クリック送り・スクロールも自動化したい
  • 対話の中で何度も撮り直したい

✅ CLI が向くケース

  • MCP 未対応の環境
  • 全スライドを一括で連番スクショしたい
  • CI / バッチ処理に組み込みたい
✅ チェックポイント
MCP なら mcp list に playwright が出る、CLI なら node shot.mjs で PNG が出力されれば Step 2 完了です。

🔁 Step 3: 自律デザインチェックループ

⏱ 20分 本資料の核心

ここが本ハンズオンの心臓部です。AI に「作って終わり」ではなく 「作る → 自分で見る → 直す」を繰り返させます。 ポイントは、具体的なチェック観点と合格条件を指示文に書き込むことです。

3-1. チェックすべきデザイン観点

AI に「何を見るか」を教えないと、ただ「良さそうです」で終わってしまいます。観点を明示しましょう。

観点NG の例AI への伝え方
はみ出し 文字や画像が画面端で切れている 「全要素がスライド枠 (1280×720) 内に収まっているか」
余白バランス 上に詰まり下が大きく空く 「コンテンツが上下左右に偏っていないか」
文字量 1枚に詰め込みすぎ 「1スライド6行以内、フォントが小さすぎないか」
コントラスト 薄い背景に薄い文字で読めない 「文字色と背景色のコントラストは十分か」
一貫性 スライドごとに見出し位置がずれる 「全スライドで見出し・余白が揃っているか」

3-2. そのまま使える「自律ループ」指示文

以下のプロンプトを、お好きなエージェントにそのまま貼り付けてください。エージェントを問わず動作します。

Marp・自作HTMLのHTTPサーバーの起動手順は、Step 5・Step 6を参照してください。

🎯 自律デザインチェックの指示テンプレート 
これからスライドを作成します。次の手順を「合格するまで」繰り返してください。

1. スライドを生成し、開発サーバーのURLを開く（Marp・自作HTMLの場合は、人が別の端末で起動したHTTPサーバーのURL http://127.0.0.1:8000/slides.html を開く）
2. Playwright で各スライドのスクリーンショットを撮る
3. 撮った画像を自分で確認し、以下の観点で採点する：
   - 文字や画像が枠 (1280×720) からはみ出していないか
   - 余白が上下左右で極端に偏っていないか
   - 1スライドの情報量は適切か（6行以内・フォントが小さすぎない）
   - 背景と文字のコントラストは十分か
   - 全スライドで見出し位置・余白が揃っているか
4. 問題があれば原因を1つずつ説明し、コードを修正する
5. 修正後にもう一度スクショを撮り、2〜4を繰り返す
6. すべての観点を満たしたら「合格」と報告し、最終スクショを見せる

各ラウンドで「今ラウンドで直した点」を箇条書きで報告してください。
無限ループを避けるため、最大5ラウンドで一旦止めて報告してください。

3-3. ループの流れ（イメージ）

生成Markdown/HTML
→
表示localhost
→
撮影screenshot
→
採点5観点チェック
→
判定合格 or 再修正
⚠️ 無限ループ・暴走を防ぐ
「最大 5 ラウンドまで」「コストが気になったら一旦止めて報告して」など上限を指示に入れておくと安心です。 また、毎ラウンド「何を直したか」を報告させることで、AI が同じ修正を繰り返していないか人間が監視できます。
💡 なぜ効くのか
LLM はテキストだけでは「見た目の崩れ」を想像できません。 実際の描画結果（画像）を入力に戻すことで初めて、人間のレビュアーと同じ土俵に立てます。 これが「マルチモーダル × 自己修正」の威力です。

🔵 Step 5: Marp でスライドを作る

⏱ 15分

Marp は「ただの Markdown」でスライドを書ける最もシンプルなツールです。 VS Code 拡張も人気で、とにかく速くスライド化したいときに最適です。

5-1. Marp の Markdown 構造

先頭に marp: true を書くだけ。--- がスライド区切りです。

---
marp: true
theme: default
paginate: true
---

# AI 駆動開発入門

発表者: あなたの名前

---

## アジェンダ

1. AI エージェントとは
2. スライド自動生成
3. 自律デザインチェック

---

## まとめ

- AI に「見て直す」を任せられる時代
- まずは小さなお題から

5-2. プレビューと書き出し

# HTML プレビューを生成
npx @marp-team/marp-cli@latest slides.md -o slides.html

# PDF に書き出し
npx @marp-team/marp-cli@latest slides.md --pdf

# 監視モード（保存のたびに自動更新）
npx @marp-team/marp-cli@latest -w slides.md -o slides.html

5-3. AI への実習プロンプト

slides.html があるフォルダで npx --yes http-server . -a 127.0.0.1 -p 8000 を実行し、この端末は開いたままにします。Playwrightでは http://127.0.0.1:8000/slides.html を開きます。

🎯 演習: Marp で同じ内容を作り、見た目を比較する 
Marp で「AI 駆動開発入門」のスライド（slides.md）を作成してください。
theme は default、paginate は true。

作成後:
1. marp CLI で slides.html を生成
2. Playwright で各スライドのスクショを撮る
3. Step 3 の観点でチェックし、はみ出しや文字過多を修正
4. 最後に PDF も書き出してください
🎨 テーマのカスタマイズ
Marp は <style> を Markdown に直接書いたり、カスタムテーマ CSS を読み込めます。 「もっと余白を広く」「見出しを大きく」と AI に頼めば、style ブロックを追記してくれます。

🟣 Step 6: HTML スライドで作る

⏱ 15分

自由度を最優先するなら、HTML / CSS で 1 から作る方法です。 reveal.js のようなライブラリを使う方法と、完全自作する方法があります。 ブランド固有の凝ったデザインや、Web 公開を前提とする場合に向きます。

6-1. シンプルな自作 HTML スライドの骨格

<!-- 1スライド = 1セクション。CSS Scroll Snap でページ送り -->
<style>
  html { scroll-snap-type: y mandatory; }
  .slide {
    width: 100vw; height: 100vh;          /* 16:9 を意識 */
    scroll-snap-align: start;
    display: flex; flex-direction: column;
    justify-content: center; align-items: center;
    padding: 5vw;
  }
  @media print {
    @page { size: 1280px 720px; margin: 0; }
    body { margin: 0; }
    .slide {
      box-sizing: border-box;
      width: 1280px; height: 720px;
      break-after: page;
    }
  }
</style>

<section class="slide"><h1>AI 駆動開発入門</h1></section>
<section class="slide"><h2>アジェンダ</h2></section>

6-2. reveal.js を使う場合

# CDN を読み込むだけで使える（AI が雛形を生成）
# https://revealjs.com/ の <section> 区切りでスライドを書く

6-3. AI への実習プロンプト

slides.html があるフォルダで npx --yes http-server . -a 127.0.0.1 -p 8000 を実行し、この端末は開いたままにします。Playwrightでは http://127.0.0.1:8000/slides.html を開きます。

🎯 演習: 世界観のある HTML スライドを作る 
HTML/CSS だけで「AI 駆動開発入門」のスライド（slides.html）を作成してください。
要件:
- 1スライド = 1画面（16:9, 1280×720想定）
- CSS Scroll Snap で縦スクロールのページ送り
- ダークテーマ + 紫のアクセント、Google Fonts 使用

作成後、Playwright で各画面をスクショし、

⚠️ HTML 自作の注意点
自由度が高い分、AI が崩しやすいのも HTML です。だからこそ Step 3 の自律デザインチェックが最も効果を発揮します。 必ずスクショで実物を確認させましょう。

🤖 エージェント別の指示のコツ

基本のプロンプトは共通ですが、各エージェントの個性に合わせると、より快適に進められます。

Claude Code

  • CLAUDE.md に「スライドは1枚6行以内」「16:9」などのルールを書いておくと、Claude Codeが作業時に参照します。ただし、必ず守られるとは限りません。
  • 長い反復に強い。自律ループを最後まで粘り強く回せる
  • スクショ画像をそのまま会話に貼って指摘するのも有効

Codex

  • サンドボックス / クラウド実行で、スクショ生成スクリプトを安全に試せる
  • 「まず計画を出して」と一段挟むと、構成が安定する
  • PR まで自動化したい場合は Codex の Git 連携が便利

Antigravity

  • 並列マルチエージェントで「Slidev 版」「Marp 版」を同時に作らせる使い方が強力
  • Worktree 制御で、形式ごとにブランチを分けて作業できる
  • ビジュアル生成と組み合わせて表紙画像まで作るのも◎
💡 共通の鉄則
どのエージェントでも「具体的に・段階的に・実物を見せて」が効きます。 これは Vibe Coding の3原則 と同じです。

📤 PDF / 画像へのエクスポート

⏱ 5分

発表本番では PDF が安心です。各形式の書き出しコマンドをまとめます。

Slidev はプロジェクトのフォルダで npm install -D playwright-chromium を実行してから書き出します。Marp は Chrome・Edge・Firefox のいずれかが必要です。

形式PDF 書き出し画像（PNG）書き出し
Slidev npx slidev export npx slidev export --format png
Marp npx @marp-team/marp-cli@latest slides.md --pdf npx @marp-team/marp-cli@latest slides.md --images png
HTML Playwright の page.pdf() / ブラウザ印刷 Playwright の page.screenshot()

HTML を Playwright で PDF 化する例

slides.html があるフォルダで npx --yes http-server . -a 127.0.0.1 -p 8000 を実行し、この端末は開いたままにします。Playwrightでは http://127.0.0.1:8000/slides.html を開きます。

// to-pdf.mjs
import { chromium } from 'playwright';

const browser = await chromium.launch();
const page = await browser.newPage();
await page.goto('http://127.0.0.1:8000/slides.html');
await page.pdf({ path: 'slides.pdf', preferCSSPageSize: true, printBackground: true });
await browser.close();

方法Bの準備を済ませ、別の端末で同じフォルダを開いて node to-pdf.mjs を実行します。

📌 発表直前のチェック
「全スライドを PNG にして、サムネイル一覧として並べて見せて」と AI に頼むと、 発表前の最終目視が一気に楽になります。

💡 活用 Tips 集

Tips 1: ビューポートは必ず 16:9 で固定

スクショの viewport を 1280×720（または 1920×1080）に固定すると、AI のチェックが実際の発表画面と一致します。

Tips 2: 「採点表」を出させる

各スライドについて、5観点（はみ出し/余白/文字量/コントラスト/一貫性）を
○△× で採点した表を出してから、× の項目だけ直してください。

Tips 3: 元ネタは箇条書きで渡す

長文の原稿より、箇条書きのアウトラインを渡すほうが構成が安定します。「この箇条書きを6枚のスライドに分割して」が鉄板です。

Tips 4: テーマ替えは一瞬

Slidev / Marp なら theme: を変えるだけで全体の印象が変わります。「3パターンのテーマで作り比べて、スクショを並べて」も可能です。

Tips 5: 1枚ずつ撮らせる

全体を1枚に撮るより、スライドごとに連番スクショさせたほうが、AI が崩れを正確に検出できます。

チートシート

やりたいことプロンプト例

スライド生成「このアウトラインを Slidev のスライドにして」
見た目チェック「Playwright で全スライドを撮って崩れを直して」
テーマ比較「3テーマで作ってスクショを並べて見せて」

🧩 Skill 化して資産にする

⏱ 10分

ここまでの「作る → 見て直す」を毎回ゼロから指示するのは大変です。 今回のハンズオンで学んだ核心を Claude Code の Skill（SKILL.md ＋付属ファイル）に落とし込んでおけば、 次回からは「Slidev でスライド作って」の一言で同じ品質が再現できます。 おすすめは、役割の違う 2つの Skill に分けることです。

📌 なぜ2つに分けるのか
「作る（型・ルール・スタイルの適用）」と「見て直す（実描画レビューの自律ループ）」は 目的も使うツールも違います。分けておくと、デッキ作成時は前者、仕上げ時は後者、と用途に応じて呼び分けられます。

1. slidev-deck-build — スライドを作る Skill

「型」と「守るべきルール」「実証済みのスタイル」をパッケージ化します。

slidev-deck-build/
├── SKILL.md                  作成手順・型・守るべきルール
├── assets/slidev-style.css   このデッキで実証済みのグローバル CSS（そのままコピーして使う）
└── reference/patterns.md     9種の図示パターン（IN/OUT・統計・カードグリッド・比較表・
                              マトリクス・事例フロー・2軸散布図・階層フロー・CTA）＋配色トークン

このプロジェクトで学んだ核心を、手順とルールに落とし込みます。

  • 共通スタイルは style.css に集約する — スライド内の <style> は他スライドに波及しないため、共通の見た目はグローバル CSS に置く
  • 見出し＝短いラベル＋.lead＝主張一文 — 1ページ1メッセージを徹底する
  • 数字は .big-stat で主役化 — 統計値は大きく見せて視線を集める
  • export は --wait 3000 — 描画完了を待ってから書き出し、崩れを防ぐ
  • 章番号は連番 — セクションの通し番号で構成の見通しを良くする

2. slidev-design-review — Playwright 自律改善 Skill

「描画 → 目視診断 → 修正 → 再描画で検証」の自律ループをパッケージ化します。

slidev-design-review/
├── SKILL.md            描画→目視診断→修正→再描画検証の自律ループ
├── assets/shoot.mjs    スクショ撮影（node shoot.mjs 1-51 / 2,5,14 の範囲・個別指定対応）
└── assets/probe.mjs    computed style 実測（スタイル未適用の切り分け）

今回ハマった落とし穴を、すべて Skill 側のノウハウとして固定化します。

  • <style> のスコープ問題は computed style 実測で切り分ける — 例えば .lead の border が 0px なら CSS が未適用、と機械的に判定できる
  • ?print=cover / live=default でレイアウトクラスが変わる — CSS セレクタを両対応にしないと、dev では直って見えても PDF で崩れる
  • スクショは 1000px・1枚ずつ Read する — まとめ撮りより崩れを正確に検出できる。playwright-chromium は node_modules のあるディレクトリから実行する
  • 「直したつもり」で終わらせず、必ず再描画で確認する — 修正後にもう一度撮って、本当に直っているかを目視する
💡 作り方のヒント
Skill の雛形づくりに迷ったら、Claude Code に 「slidev-deck-build という Skill を作りたい。SKILL.md と assets/、reference/ の構成で、 上の核心ルールを手順に落として」と頼めば、土台を一気に生成できます。 作った Skill は ~/.claude/skills/ に置けば、どのプロジェクトからでも呼び出せます。
Skillいつ使う呼び出し例
slidev-deck-build新規にデッキを作る・再構成する「この資料を 1ページ1メッセージでスライド化して」
slidev-design-review作ったデッキの仕上げ・崩れ修正「Playwright で実描画レビューして直して」
