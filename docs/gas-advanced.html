発展編

🚀 生成AI活用コーディングハンズオン
～ Google Apps Script (GAS) 応用と発展 ～

初級編で作ったタスク通知アプリに、生成 AI を相棒にしてオリジナルの機能を追加していきます。「自分でゼロから書く」のではなく「AI に書かせて動かす」体験がテーマです。

前提: 初級編のタスク通知アプリが完成していること

🙋 みなさんの進捗状況を知りたいので、うまく進んでいる場合も、進んでいない場合も絵文字リアクションを積極的に返してください！進んでないよ、というときも遠慮なく！

はじめに

ℹ️ この発展編は初級編の続きです。まだの方は先に 初級編（タスク通知アプリ作成） を完了させてから戻ってきてください。

初級編では、毎日のタスクを Gmail で自動通知するアプリを作りました。発展編では、各自が契約・利用している文章系の生成 AI（ChatGPT / Gemini / Claude など）を活用して、このアプリにオリジナルの要素を付け加えていきます。

🎯 この発展編のゴール

  • 「やりたいこと」を生成 AI に伝えてコードを書いてもらう進め方のコツを身につける
  • タスク通知アプリを 8 つの方向に拡張する例を体験する（まとめ送信 / 優先度 / 完了管理 / カレンダー連携 / Gemini API / チャット通知 / エラー通知 / AI による判定）
  • エラーが出ても、AI に質問しながら自走できるようになる

基本姿勢

Step 1: 生成 AI を相棒にする「進め方」

基本の進め方は、初級編の「🤖 このハンズオンの進め方」を確認してください。

🔑 AI に質問するときの 3 つのコツ

  1. 今のスクリプトを丸ごと貼り付ける … AI はあなたのコードを見られません。まずは現状のコード全文を貼り、その上で依頼します。
  2. 「何をしたいか」を一文で伝える … 例:「このスクリプトの複数のタスクのお知らせを1つのメールで送信できるようにして」
  3. エラーはそのままコピペして聞く … 実行ログに出たエラー文を貼って「このエラーの原因と直し方を教えて」と聞くのが最速です。
💡 基本のプロンプトのかたち
（スクリプトを全文貼り付け） の後に、改行して ↑このスクリプトで、〇〇できるようにして と添えるだけ。これだけで AI が書き換え案を返してくれます。

📬 まとめ送信

Step 2: 複数タスクを 1 通のメールにまとめる

初級編のコードは、今日のタスクが 3 件あればメールも 3 通届いてしまいます。これを1 通にまとめて送るように変えてみましょう。

📬 「送る場所」でメールの数が変わる
🤖 Gemini にこう聞く
（いまのコードを全文貼り付けてから）このスクリプトの複数のタスクのお知らせを1つのメールで送信できるようにして
💡 うまくいかないとき / 答え合わせ用のコードを見る

ポイントは、forEach でその都度送るのをやめて、いったん本文を 1 つの文字列に組み立ててから、最後に 1 回だけ送ることです。

// 今日のタスク（tasksToday）が抽出された後...

// タスクが1件もなければ送らない
if (tasksToday.length === 0) return;

const recipientEmail = 'your.email@example.com'; // 自分のアドレスに置き換える

// 本文を1つにまとめる（箇条書き）
let body = '本日のタスクは以下の通りです。<br><ul>';
tasksToday.forEach(task => {
  body += `<li>${task[0]}</li>`; // task[0] = タスク名
});
body += '</ul>';

// まとめて1通だけ送信
MailApp.sendEmail({
  to: recipientEmail,
  subject: `本日のタスク（${tasksToday.length}件）`,
  htmlBody: body
});
ℹ️ htmlBody に <ul><li> などの HTML タグを書くと、メールが箇条書きで見やすく表示されます。

🔺 優先度

Step 3: タスクに優先度を追加する

タスクの重要度に応じて優先度を設定し、通知で強調表示することで、重要なタスクに注意を向けやすくできます。

📋 準備

  1. スプレッドシートに C 列「優先度」を追加し、各行に「高」「中」「低」などの値を入力する
🤖 Gemini にこう聞く
（いまのコードを全文貼り付けてから）↑スプレッドシートの C 列に「優先度」（高・中・低）を追加しました。このスクリプトに、タスクの優先度を追加できるようにして
💡 うまくいかないとき / 答え合わせ用のコードを見る

優先度の列を読み取り、値に応じてメッセージを変えます。列の番号は 0 から数えるので、A列＝task[0]、B列＝task[1]、C列＝task[2] になります。

列中身コードでの書き方
Aタスク名task[0]
B実施日task[1]
C優先度task[2]
// タスクが1件もなければ送らない
if (tasksToday.length === 0) return;

const recipientEmail = 'your.email@example.com'; // 自分のアドレスに置き換える

// 優先度を反映しながら、本文を1つにまとめる
let body = '本日のタスクは以下の通りです。<br><ul>';
tasksToday.forEach(task => {
  const taskName = task[0];
  const priority = task[2]; // 優先度を取得

  // 優先度に応じてメッセージを変更
  let message = taskName; // 先に既定を入れておくと「中」や空欄のときの else が要らない
  if (priority === "高") {
    message = `<strong>🔺 重要!</strong> ${taskName}`;
  } else if (priority === "低") {
    message = `${taskName} (優先度: 低)`;
  }

  body += `<li>${message}</li>`;
});
body += '</ul>';

// まとめて1通だけ送信
MailApp.sendEmail({
  to: recipientEmail,
  subject: `本日のタスク（${tasksToday.length}件）`,
  htmlBody: body
});

✅ 完了管理

Step 4: タスクの完了状況を管理する

完了状況をスプレッドシートで管理し、未完了のタスクだけ通知すれば、終わったタスクの通知に煩わされなくなります。

📋 準備

  1. スプレッドシートに D 列「完了状況」を追加する（Step 3 で C 列まで使ったので、その隣）
  2. タスクが終わったら「完了」と入力する
🔎 D 列をふるいにして未完了だけ残す
🤖 Gemini にこう聞く
（いまのコードを全文貼り付けてから）↑スプレッドシートの D 列に「完了状況」を追加しました。このスクリプトで、タスクが未完了のものだけ通知するようにして
💡 うまくいかないとき / 答え合わせ用のコードを見る

完了状況の列（D 列＝task[3]）が「完了」のものを通知対象から外し、未完了のタスクだけを1通にまとめます。

列中身コードでの書き方
Aタスク名task[0]
B実施日task[1]
C優先度task[2]
D完了状況task[3]
// D列が「完了」ではないタスクだけに絞る
const incompleteTasks = tasksToday.filter(task => task[3] !== "完了");

// 未完了のタスクが1件もなければ送らない
if (incompleteTasks.length === 0) return;

const recipientEmail = 'your.email@example.com'; // 自分のアドレスに置き換える

// 優先度を反映しながら、本文を1つにまとめる
let body = '本日の未完了タスクは以下の通りです。<br><ul>';
incompleteTasks.forEach(task => {
  const taskName = task[0];
  const priority = task[2];

  let message = taskName; // 先に既定を入れておくと「中」や空欄のときの else が要らない
  if (priority === "高") {
    message = `<strong>🔺 重要!</strong> ${taskName}`;
  } else if (priority === "低") {
    message = `${taskName} (優先度: 低)`;
  }

  body += `<li>${message}</li>`;
});
body += '</ul>';

// まとめて1通だけ送信
MailApp.sendEmail({
  to: recipientEmail,
  subject: `本日の未完了タスク（${incompleteTasks.length}件）`,
  htmlBody: body
});
💡 filter で先に未完了のタスクだけへ絞ると、メール本文の組み立てと件数の表示を分かりやすく保てます。

📅 カレンダー連携

Step 5: Google カレンダーと連携する

Google カレンダーの予定をタスクとして扱い、Gmail で通知すれば、スケジュール管理とタスク管理を統合できます。

📅 タスク配列の後ろに今日の予定を足す
🤖 Gemini にこう聞く
（いまのコードを全文貼り付けてから）このスクリプトで、Google カレンダーから今日の予定も取ってきて、タスクと一緒に通知できるようにして
💡 うまくいかないとき / 答え合わせ用のコードを見る

GAS には標準で CalendarApp が用意されており、その日の予定を簡単に取得できます。取得した予定を、タスクの配列に追加してから通知します。

// Google カレンダーから今日の予定を取得
const calendarId = 'your.calendar.id@group.calendar.google.com'; // カレンダー ID に置き換える
const calendar = CalendarApp.getCalendarById(calendarId);

// ID が間違っていると null になるので、そのときは予定なしとして進む
const events = calendar ? calendar.getEventsForDay(today) : [];

// 予定をタスクとして追加
events.forEach(event => {
  tasksToday.push([event.getTitle(), formattedToday, '中', '未完了']);
});

// ...（この後、通常どおり Gmail 通知を送信）...
ℹ️ カレンダー ID は、Google カレンダーの「設定と共有」→「カレンダーの統合」から確認できます。自分のメインカレンダーなら、ご自身の Gmail アドレスがそのまま ID になります。
⚠️ カレンダー ID を置き換えないと予定は 0 件になります。 ID が違うと getCalendarById は null を返します。上のコードは、そのときエラーで止まらず「予定なし」として進むようにしてあります。予定が出てこないときは、まず ID を見直してください。
ℹ️ 「承認が必要です」がまた出ます。 Google カレンダーを読む権限が新しく要るためです。「権限を確認」を押し、アカウント選択が出たら自分のアカウントを選びます。次に表示された画面に合わせて進みます。
  • 英語の小さなダイアログで、アプリ名の横に (Unverified) と出た場合：「REVIEW PERMISSIONS」を押すと、次の日本語の画面へ進みます。
  • 「このアプリは Google で確認されていません」と出た場合：「詳細」→「（プロジェクト名）（安全ではないページ）に移動」を選択します。
下までスクロールして「許可」を押します。権限ごとのチェック欄がある場合は、すべてにチェックを入れてから「許可」を押します。チェックしないと実行時にエラーになります。

Step 6: 文章生成 AI（Gemini API）の活用

仕上げに、Gemini を GAS から呼び出して、タスク名から通知文を自動生成させてみましょう。たとえば秘書風の案内文を生成させる、といった使い方ができます。ここまでは画面の Gemini に聞きながら進めてきましたが、今度はスクリプトの中から Gemini を呼び出すわけです。

🌐 GAS から外部 API へ出て、文章を取り出す
🤖 Gemini にこう聞く
（いまのコードを全文貼り付けてから）このスクリプトから Gemini API を呼び出して、通知の文面を秘書風に書いてもらうように書き換えて

📋 準備

  1. Google AI Studio で API キーを取得する（普段使っている Google アカウントでそのまま作れます）。Google AI Studio／Gemini API の利用は 18 歳以上が対象です。
  2. GAS の画面左「⚙️ プロジェクトの設定」→ 一番下「スクリプト プロパティ」→「スクリプト プロパティを追加」を選ぶ。既に項目がある場合は「スクリプト プロパティを編集」から追加する
  3. プロパティ名に GEMINI_API_KEY、値に取得した API キーを入れて保存する
  4. GAS から UrlFetchApp を使って Gemini の API を呼び出す
⚠️ 無料枠の Gemini API に送った内容は、Google の製品改善や人による確認に使われることがあります。実習では架空のタスク名・予定を使い、氏名や個人的な予定は送らないでください。
💡 無料の枠内で試せます。 Gemini API には無料枠があり、クレジットカードの登録なしで始められます。このハンズオンで動かす回数なら、無料枠に十分おさまります。
💡 うまくいかないとき / 答え合わせ用のコードを見る

GAS には外部 API を叩くための UrlFetchApp があります。タスク名を渡して、件名や本文を Gemini に作らせます。

// タスク名から、秘書風の通知文を Gemini に生成してもらう関数
function generateMessage(taskName) {
  const apiKey = PropertiesService.getScriptProperties().getProperty('GEMINI_API_KEY');
  const model = 'gemini-flash-latest';  // 速くて安いモデル
  const url = `https://generativelanguage.googleapis.com/v1beta/models/${model}:generateContent`;

  const payload = {
    systemInstruction: {
      parts: [{ text: 'あなたは丁寧な秘書です。' }]
    },
    contents: [{
      parts: [{ text: `本日のタスク「${taskName}」を、秘書風に一言添えて知らせて。` }]
    }]
  };

  const options = {
    method: 'post',
    contentType: 'application/json',
    headers: { 'x-goog-api-key': apiKey }, // API キーはヘッダーで渡す
    payload: JSON.stringify(payload)
  };

  const response = UrlFetchApp.fetch(url, options);
  const json = JSON.parse(response.getContentText());
  return json.candidates[0].content.parts[0].text; // 生成された文章を返す
}

この関数を作っただけでは何も変わりません。メールを送っているところから呼び出して、生成された文章を本文に使います。

// タスクが1件もなければ送らない
if (tasksToday.length === 0) return;

const recipientEmail = 'your.email@example.com'; // 自分のアドレスに置き換える

// Gemini が作った文面を、1通分の本文にまとめる
let body = '本日のタスクは以下の通りです。<br><ul>';
tasksToday.forEach(task => {
  const taskName = task[0];

  // Gemini に秘書風の文面を書いてもらう
  const message = generateMessage(taskName);

  body += `<li>${message}</li>`;
});
body += '</ul>';

// まとめて1通だけ送信
MailApp.sendEmail({
  to: recipientEmail,
  subject: `本日のタスク（${tasksToday.length}件）`,
  htmlBody: body
});
⚠️ API キーの取り扱いに注意！ API キーはパスワードと同じです。スクリプトをそのまま他人に共有・公開すると不正利用される恐れがあります。上のコードは PropertiesService（スクリプトプロパティ）からキーを読む形です。Step 6 で登録したキーを Step 9 でも使います。
ℹ️ 「承認が必要です」がまた出ます。 UrlFetchApp で外部サービスへ接続する権限が新しく要るためです。「権限を確認」を押し、アカウント選択が出たら自分のアカウントを選びます。次に表示された画面に合わせて進みます。
  • 英語の小さなダイアログで、アプリ名の横に (Unverified) と出た場合：「REVIEW PERMISSIONS」を押すと、次の日本語の画面へ進みます。
  • 「このアプリは Google で確認されていません」と出た場合：「詳細」→「（プロジェクト名）（安全ではないページ）に移動」を選択します。
下までスクロールして「許可」を押します。権限ごとのチェック欄がある場合は、すべてにチェックを入れてから「許可」を押します。チェックしないと実行時にエラーになります。
ℹ️ モデル名に gemini-flash-latest と書いておくと、Google 側で新しい版が出たときに自動でそちらを向きます。特定の版に固定したいときは gemini-3.8-flash のようにバージョンを書きます。無料枠には1分あたり・1日あたりの回数制限があり、超えるとエラー（429）が返ります。請求の設定をしない限り、勝手に課金されることはありません。

Step 7: Slack / Discord に通知する

通知先を Gmail からチャット（Discord または Slack）へ変えます。

やり方は Step 6 と同じです。UrlFetchApp で、渡された URL へ文章を送ります。

🤖 Gemini にこう聞く
（いまのコードを全文貼り付けてから）このスクリプトの通知先を、メールではなく Discord の Webhook に変えて。Webhook の URL はスクリプトプロパティから読むようにして

📋 準備

  1. Webhook の URL を作る
    • Discord: 自分で作った練習用サーバー、または「ウェブフックの管理」権限があるチャンネルで行います。通知したいチャンネルの「⚙️ チャンネルの編集」→「連携サービス」→「ウェブフックを作成」→「ウェブフック URL をコピー」
    • Slack: Incoming Webhooks からアプリを作ってチャンネルを選ぶ
  2. URL をスクリプトプロパティに保存する
    GAS の画面左「⚙️ プロジェクトの設定」→ 一番下「スクリプト プロパティ」→「スクリプト プロパティを編集」→「スクリプト プロパティを追加」（まだ項目がない場合は直接「スクリプト プロパティを追加」）
    プロパティ名に WEBHOOK_URL、値にコピーした URL を入れて保存
💡 スクリプトプロパティは「コードの外に置く金庫」です。 Step 6 で「API キーはパスワードと同じ」と書きました。ここで使うのがその保管場所です。コードに直接書かないので、スクリプトを人に見せても URL やキーは漏れません。ただし、プロジェクトの共同編集者には保存した値が見えます。人と共有するプロジェクトには自分のキーや URL を残さないでください。
💡 うまくいかないとき / 答え合わせ用のコードを見る

まず、スクリプトプロパティから URL を読み出します。PropertiesService を使います。

// Discord に通知を送る関数
function notifyToDiscord(text) {
  // コードに URL を直接書かず、スクリプトプロパティから読む
  const webhookUrl = PropertiesService.getScriptProperties().getProperty('WEBHOOK_URL');

  const options = {
    method: 'post',
    contentType: 'application/json',
    payload: JSON.stringify({ content: text }) // Discord は content というキーで受け取る
  };

  UrlFetchApp.fetch(webhookUrl, options);
}

あとは、メールを送っていたところを、この関数の呼び出しに差し替えます。

// タスクが1件もなければ送らない
if (tasksToday.length === 0) return;

// チャットは HTML が使えないので、ただの文字列で組み立てる
let text = `**本日のタスク（${tasksToday.length}件）**\n`;
tasksToday.forEach(task => {
  text += `・${task[0]}\n`;
});

notifyToDiscord(text);
ℹ️ Slack にしたいときは 2 か所だけ変わります。 キー名が content ではなく text になることと、太字の書き方が **こう** ではなく *こう* になることです。どちらも Gemini に「Slack 用に直して」と言えば書き換えてくれます。
⚠️ Webhook の URL は、それ自体がパスワードです。 知っている人は誰でもそのチャンネルに書き込めます。スクリーンショットを撮って共有するときや、画面を共有しながら作業するときは、URL が写り込んでいないか気をつけてください。

Step 8: 止まったことに気づけるようにする

トリガーで動いている間はエディタを開いていないので、エラーが出ても画面に出ません。Apps Script 標準の失敗通知メールが届きますが、英語の定型文で、届くまで時間がかかることもあります。

ここでは try...catch で囲み、失敗したときだけ、日本語で原因が分かる通知を自分あてにメールで送るようにします。

🛡️ 画面を見ていなくても、失敗をメールで知る
🤖 Gemini にこう聞く
（いまのコードを全文貼り付けてから）この関数でエラーが出たときに、エラーの内容を自分宛てにメールで知らせるようにして。try catch を使って書き換えて
💡 うまくいかないとき / 答え合わせ用のコードを見る

処理全体を try で囲み、失敗したときの行き先を catch に書きます。いまの関数の中身はいじらず、外側を包むだけです。

function myFunction() {
  try {

    // ここに、これまで書いてきた処理をそのまま入れる
    // （スプレッドシートを読む → 絞り込む → 通知する）

  } catch (error) {
    // 失敗したときだけ、ここに来る
    MailApp.sendEmail({
      to: 'your.email@example.com', // 自分のアドレスに置き換える
      subject: '【要確認】タスク通知が失敗しました',
      body: `エラーの内容:\n${error.message}\n\n発生場所:\n${error.stack}`
    });
  }
}

うまく動いているかを確かめたいときは、console.log() で途中の値を出しておくと追いかけやすくなります。

console.log(`本日のタスクは ${tasksToday.length} 件でした`);

出力した内容は、GAS の画面左「実行数」から、いつ・どの関数が・成功したか失敗したかと一緒に確認できます。

💡 わざと失敗させて試してください。 スプレッドシート下部のシートのタブ名（「シート1」など）を一時的に「シート99」に変えてから実行すると、指定したシートが見つからずエラーになります。ここでメールが届けば、仕掛けがちゃんと働いています。確認したらタブ名を元に戻してください。
ℹ️ GAS には 1 日に使える量の上限があります。 無料アカウントの場合、メールの宛先は 1 日に延べ 100 人まで、トリガーで動く実行は 1 日の合計 90 分までです（1 回の実行は最大 6 分）。ふつうに 1 日 1 回動かす分には当たりませんが、トリガーを 5 分おきにしたり、タスク 1 件ごとに Gemini を呼んだりすると届いてしまうことがあります。

Step 9: 優先度を Gemini に決めてもらう

Step 3 では、優先度を自分で手入力しました。Step 6 では Gemini に文章を書かせました。この 2 つを合わせます。

つまり、タスク名を見て優先度が何かを Gemini に判断させるわけです。同じ Gemini でも、文章を作らせるのと、決めさせるのとでは使いどころが変わります。

🤖 Gemini にこう聞く
（いまのコードを全文貼り付けてから）タスク名を渡すと、Gemini が「高」「中」「低」のどれかだけを返す関数を作って。余計な説明は付けずに一語だけ返させて
💡 うまくいかないとき / 答え合わせ用のコードを見る

Step 6 で作った generateMessage とほぼ同じ形です。違うのは、頼み方だけ。「一語だけ返して」と釘を刺すのがコツです。

// タスク名から優先度を判定してもらう関数
function judgePriority(taskName) {
  const apiKey = PropertiesService.getScriptProperties().getProperty('GEMINI_API_KEY');
  const model = 'gemini-flash-latest';
  const url = `https://generativelanguage.googleapis.com/v1beta/models/${model}:generateContent`;

  const payload = {
    systemInstruction: {
      // 「これ以外を返すな」と強く指定するのが大事
      parts: [{ text: '優先度を判定し、「高」「中」「低」のいずれか一語だけを返してください。説明は一切不要です。' }]
    },
    contents: [{
      parts: [{ text: `タスク: ${taskName}` }]
    }]
  };

  const options = {
    method: 'post',
    contentType: 'application/json',
    headers: { 'x-goog-api-key': apiKey },
    payload: JSON.stringify(payload)
  };

  const response = UrlFetchApp.fetch(url, options);
  const json = JSON.parse(response.getContentText());
  const result = json.candidates[0].content.parts[0].text.trim();

  // 想定外の答えが返ってきたときの逃げ道を用意しておく
  return ['高', '中', '低'].includes(result) ? result : '中';
}

この関数を作っただけでは何も変わりません。本文を組み立てているところから呼び出して、判定された優先度を表示に使います。

// 本文を組み立てるところで、優先度を Gemini に判定してもらう
let body = '本日のタスクは以下の通りです。<br><ul>';

tasksToday.forEach(task => {
  const taskName = task[0];

  // C 列の値を使う代わりに、Gemini に判定させる
  const priority = judgePriority(taskName);

  let message = taskName;
  if (priority === "高") {
    message = `<strong>🔺 重要!</strong> ${taskName}`;
  } else if (priority === "低") {
    message = `${taskName} (優先度: 低)`;
  }

  body += `<li>${message}</li>`;
});
body += '</ul>';
💡 最後の 1 行が肝です。 「一語だけ返して」と頼んでも、AI が「優先度は高です」と返してくることがあります。そのまま使うと表示が崩れるので、想定した 3 つ（「高」「中」「低」）以外が返ってきたときは「中」にする、と決めておきます。
⚠️ タスクの数だけ API を呼びます。 タスクが 20 件あれば 20 回です。無料枠には 1 分あたりの回数制限があるので、件数が多いときはエラー（429）が返ることがあります。全部のタスクを 1 回のリクエストでまとめて判定させる書き方もあります。「タスク一覧をまとめて渡して、優先度を一度に判定させて」と Gemini に聞いてみてください。
