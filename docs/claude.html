🧠 Claude Code とは

Claude Code は、Anthropic が開発したターミナルベースの AI コーディングエージェントです。 2025年2月にベータ版が公開され、同年5月に正式リリースされました。

主な特徴

  • 🖥️ ターミナルで動作: ブラウザ不要、CLI からすぐに使える
  • 📁 ファイル読み書き: プロジェクト全体を理解してコードを生成・修正
  • ⚡ コマンド実行: テスト実行・ビルド・デプロイまで自動化
  • 🔌 MCP 対応: Model Context Protocol で外部ツールと連携
  • 📋 CLAUDE.md: プロジェクト固有のルールを AI に記憶させられる
  • 🔀 Git 統合: コミット・PR 作成を自然言語で指示

他の AI コーディングエージェントとの比較

ツール 提供元 動作場所 モデル 特徴
Claude Code Anthropic ターミナル Claude Opus 5.5 / Sonnet 5 / Haiku 4.5 など MCP, CLAUDE.md, 長文コンテキスト
Codex CLI OpenAI ターミナル GPT-6 系 オープンソース, マルチモーダル
Antigravity Google IDE（エージェント型） Gemini 3.1 Pro / Claude / GPT-OSS Mission Control, マルチエージェント
GitHub Copilot GitHub / MS IDE + CLI GPT-5 系, Claude IDE 統合, コード補完

2026年9月27日確認。選べるモデルは契約や接続先によって異なります。

💡 Claude Code の強み
特に長いコードベースの理解と、CLAUDE.md による「プロジェクトのルールを覚える」能力が優れています。 大規模リファクタリングや複数ファイルにまたがる変更が得意です。

⚙️ Step 1: インストール & セットアップ

⏱ 30分

1-1. Node.js の確認

# Node.js バージョン確認（Node.js 22以上のサポート中のLTS版が必要）
node --version

# npm バージョン確認
npm --version
⚠️ Node.js が古い場合
nodejs.org から最新 LTS 版をインストールしてください。 または nvm（Node Version Manager）でバージョンを切り替えることもできます。

1-2. Claude Code のインストール

# npm でグローバルインストール
npm install -g @anthropic-ai/claude-code

# インストール確認
claude --version

1-3. Anthropic API キーの取得（APIキーを使う場合）

対応プランでログインする場合は、APIキーを設定せず claude を起動します。

  1. console.anthropic.com にアクセス
  2. アカウントを作成 / ログイン
  3. 「API Keys」→「Create Key」
  4. キーをコピー（表示は一度だけ）

API利用は原則前払いです。Consoleの「Settings → Billing」で残高を確認し、不足する場合は支払い担当者が「Buy credits」から購入します。

💰 料金について
Claude Codeに対応する有料プラン・組織の利用権、またはConsoleのAPI利用が必要です。 APIキーは必須ではありませんが、APIキーで使った分は月額プランとは別料金です。 API利用の場合、ハンズオン（2時間程度）の使用で概ね $1〜3 程度です。 Claude Haiku 4.5 など軽量モデルを選ぶとよりコストを抑えられます。

1-4. API キーの設定（APIキーを使う場合）

対応プランでログインする場合は、APIキーを設定せず claude を起動します。

# 環境変数に設定（今のターミナルセッションのみ有効）
export ANTHROPIC_API_KEY="sk-ant-..."

# 永続化する場合（macOS・Zshの場合、~/.zshrc に追記）
echo 'export ANTHROPIC_API_KEY="sk-ant-..."' >> ~/.zshrc
source ~/.zshrc

1-5. 起動確認

# プロジェクトフォルダに移動
cd ~/Documents

# Claude Code を起動
claude

# 「Welcome to Claude Code」が表示されれば成功！
✅ チェックポイント
ターミナルに > プロンプトが表示され、日本語で質問できたら Step 1 完了です。

📝 Step 3: CLAUDE.md で AI をカスタマイズ

⏱ 15分

CLAUDE.md は、プロジェクトのルートに置くマークダウンファイルです。 Claude Code はこのファイルを常に読み込み、プロジェクト固有のルールや文脈を理解した上で作業します。

なぜ CLAUDE.md が必要なのか？

❌ CLAUDE.md なし

  • 毎回「このプロジェクトは〜」と説明が必要
  • コーディング規約を毎回指示する必要がある
  • チーム内でばらばらな指示になりがち

✅ CLAUDE.md あり

  • プロジェクトの文脈を自動で理解
  • コーディング規約を毎回説明不要
  • チーム全員が同じルールで AI を使える

3-1. CLAUDE.md の自動生成

# プロジェクトフォルダで Claude Code を起動し、/init を実行
claude
> /init

Claude がプロジェクトを自動解析して CLAUDE.md のたたき台を生成します。

3-2. CLAUDE.md の書き方

# プロジェクト設定: マイポートフォリオ

## プロジェクト概要
個人ポートフォリオサイト。HTML/CSS/JavaScript のみ使用。

## コーディング規約
- 変数名・関数名: camelCase を使用
- ファイル名: kebab-case を使用（例: my-component.js）
- インデント: スペース 2 個
- コメントは日本語で書く

## 使用技術
- HTML5 / CSS3 / Vanilla JavaScript
- Tailwind CSS（CDN 使用）

## 重要なルール
- レスポンシブデザイン必須（スマホ対応）
- アクセシビリティを考慮（alt 属性など）
- 不要なライブラリを追加しない

## ファイル構造
docs/
  index.html  # メインページ
  style.css   # スタイル
  script.js   # JavaScript
  img/        # 画像フォルダ

3-3. メモリ機能（~/.claude/CLAUDE.md）

プロジェクト固有の設定は プロジェクトルート/CLAUDE.md に、 全プロジェクト共通のルールは ~/.claude/CLAUDE.md に書けます。 

# ~/.claude/CLAUDE.md の例
## グローバル設定

- 回答は常に日本語で
- コードには必ずコメントを追加する
- エラーは原因と解決策をセットで提示する
- 長いコードは要所に分割して説明する
💡 Tips
CLAUDE.md はチームでバージョン管理（Git）できます。 チーム全員が同じ AI 設定で作業できるのが大きなメリットです。
🎯 演習: このリポジトリの CLAUDE.md を確認してみよう 
> CLAUDE.md の内容を読んで、このプロジェクトのルールをまとめて説明してください

🔌 Step 4: MCP（Model Context Protocol）連携

⏱ 20分

MCP（Model Context Protocol） は、Anthropic が策定した AI エージェントと外部ツールを繋ぐ標準規格です。 Claude Code は MCP サーバーを追加することで、ブラウザ操作・データベース接続・外部サービス連携などが可能になります。

MCP のしくみ

📡 MCP とは
Claude ↔ MCP サーバー ↔ 外部ツール（ブラウザ、DB、Slack…）

MCP サーバーは「プラグイン」のようなもの。追加するだけで Claude の能力が拡張されます。

4-1. 人気の MCP サーバー

MCP サーバー機能用途
Playwright ブラウザ自動操作 Web スクレイピング、E2E テスト
Filesystem ファイル操作の拡張 大規模ファイル管理
GitHub GitHub API 連携 Issue 作成, PR レビュー
Slack Slack 送受信 通知の自動化
SQLite DB クエリ実行 データ分析
Fetch Web ページ取得 リサーチ、ドキュメント参照

4-2. MCP サーバーの追加方法

# Playwright MCP を追加する例
claude mcp add playwright -- npx @playwright/mcp@latest

# 追加済みの MCP 一覧を確認
claude mcp list

# MCP を削除
claude mcp remove playwright

4-3. 設定ファイル（.mcp.json）での管理

プロジェクト直下の .mcp.json に保存し、Claude Codeで使用を承認してから /mcp で接続を確認します。

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

GitHub連携は、GitHub公式の github/github-mcp-server のClaude Code向け手順で設定します。

4-4. MCP を使った実践例

🌐 例: Playwright でブラウザを自動操作 
# Playwright MCP を追加後、Claude Code で:
> ブラウザで https://example.com を開いて、
  ページのタイトルと主要なテキストを取得してください
💡 MCP のエコシステム
公式・コミュニティ製の MCP サーバーが急速に増えています。 modelcontextprotocol/servers で検索できます。

🎨 Step 5: Vibe Coding 実践編

⏱ 20分

Vibe Coding とは、詳細な仕様を書かず「雰囲気」で自然言語の指示だけでコードを作る開発スタイルです。 Claude Code を使ってランディングページを一から作りましょう。

Vibe Coding の 3 原則

原則 1

具体的に伝える

「かっこよくして」より「黒背景にネオンカラーのグラデーション」と書く

原則 2

段階的に進める

一度に全部頼まず、構造→デザイン→機能の順で追加していく

原則 3

フィードバックする

「ここは赤にして」「このアニメーションを消して」と細かく調整する

5-1. 演習: AI カフェのランディングページを作ろう

🎯 課題: AI Café のランディングページを Claude Code で作成

以下のプロンプトをそのままコピーして使ってください。

① まず構造を作る

> 「AI Café Tokyo」というカフェのランディングページ（index.html）を作成してください。
  構成:
  - ヒーローセクション（キャッチコピー + CTAボタン）
  - メニューセクション（コーヒー3種、スムージー3種）
  - 特徴セクション（AI注文システム、顔認証決済、パーソナライズ提案）
  - アクセスセクション
  - フッター
  デザイン: ダークモード、近未来感、グラデーション背景

② デザインを洗練させる

> デザインをさらに改善してください：
  - フォントを Google Fonts の "Orbitron" と "Noto Sans JP" を使用
  - ヒーローセクションにアニメーション（フェードイン + スライド）を追加
  - メニューカードにホバーエフェクトを追加
  - スクロールするとナビが固定されるようにして

③ レスポンシブ対応

> スマホでも綺麗に表示されるようにレスポンシブデザインを実装してください。
  ブレークポイント: 768px（タブレット）, 480px（スマホ）
⏩ 早く終わった人へ：自分だけのオリジナリティを加えよう

お手本どおりに作れた人は、ここからが本番です。同じプロンプトをなぞるだけでは Claude Code の本当の力は引き出せません。「あなたが作りたいもの」を自分の言葉で伝える練習をしてみましょう。下のヒントから気になるものを選んで、プロンプトを書き換えてみてください。

  • テーマを自分ごとに： 「AI Café」を、自分が本当に作りたいサービス・お店・ポートフォリオに変えてみる。題材が変わるとデザインも構成も変わります。
  • インタラクションを足す： 「ダークモード切り替えボタン」「メニューを絞り込むフィルター」「お問い合わせフォーム（バリデーション付き）」など、動きのある機能を 1 つ追加依頼してみる。
  • ファイルを分割させる： 「CSS と JavaScript を別ファイルに分離して、保守しやすい構成にリファクタリングして」と頼み、Claude Code のファイル横断編集を体験する。
  • テストや README を書かせる： 「このページの使い方をまとめた README.md を作って」「主要な関数に動作確認用のコメントを追加して」など、コード以外の成果物も任せてみる。
  • AI に相談する： 「このサイトをもっと魅力的にするアイデアを 3 つ提案して」と聞き、提案の中から良いものを選んで実装させる。発想を AI に手伝ってもらうのも立派なスキルです。

💬 余裕があれば、Step 6 の Git / PR 自動化まで進めて、作ったページを自分のリポジトリにコミット＆PR 作成まで一気通貫で体験してみましょう。

5-2. 効果的なプロンプトのコツ

避けるべき書き方良い書き方
「いい感じにして」 「白背景に青のアクセントカラー、角丸8px のカードデザイン」
「全部まとめて作って」 「まずヒーローセクションだけ作って、確認してから次に進む」
「バグ直して」 「ボタンをクリックすると〇〇のエラーが出る。コードを確認して直して」
「追加して」 「ナビゲーションバーの右端に、ダークモード切り替えボタンを追加して」

🔀 Step 6: Git / PR を自動化する

⏱ 20分

Claude Code は Git コマンドも理解しているため、コミット・ブランチ作成・PR 作成も自然言語で指示できます。

6-1. 基本的な Git 操作

# 変更内容を確認してコミット
> 変更内容を確認して、適切なコミットメッセージで git commit してください

# 新しいブランチを作ってコミット
> feature/add-dark-mode というブランチを作成して、
  ダークモード機能を実装してコミットしてください

# コミットメッセージを日本語で
> 今の変更を「feat: ダークモード機能を追加」というメッセージでコミットして

6-2. PR（Pull Request）の自動作成

GitHub CLI（gh）がインストールされていれば、PR 作成まで自動化できます。

# GitHub CLI のインストール（Mac）
brew install gh

# GitHub にログイン
gh auth login

# Claude Code で PR を作成
> 現在の変更をまとめて、GitHub に PR を作成してください。
  タイトルと説明は日本語で、変更内容をわかりやすくまとめてください。

6-3. コードレビュー支援

# PR のコードをレビューしてもらう
> このコードの変更をレビューしてください。
  問題点・改善点・セキュリティリスクがあれば指摘してください。

# レビューコメントを反映
> レビューで指摘された「関数が長すぎる」問題を修正してください。
  50行以内に分割して、テストも追加してください。

6-4. 実習: フルサイクル Vibe Coding

🎯 演習: コード作成 → コミット → PR 作成の全工程
  1. このリポジトリを fork して clone する
  2. Claude Code で新機能を実装する
  3. 自動でコミットメッセージを生成してもらう
  4. PR の説明文も Claude に書いてもらう
> docs/ フォルダに自分の自己紹介ページ（profile.html）を追加してください。
  完成したら feature/add-profile ブランチを作り、
  PR を作成してください。PR の説明も日本語で書いてください。

💡 活用 Tips 集

Tips 1: コンテキストを意識する

Claude Code には会話の長さ（コンテキスト）に上限があります。長い作業では定期的に /compact でコンテキストを圧縮しましょう。

> /compact
# これまでの会話を要約して、同じ会話を続ける

Tips 2: スクリーンショットで UI 改善

Claude Codeにはスクリーンショットを添付して、画面の改善を依頼できます。

> [スクリーンショットを添付]
  このデザインをより洗練させてください。
  特にボタンのデザインとフォントを改善してください。

Tips 3: エラーはそのままペースト

エラーメッセージはそのまま貼り付けるだけで原因分析と修正案を提示してくれます。

> 以下のエラーが発生しました。原因と修正方法を教えてください：

TypeError: Cannot read properties of undefined (reading 'map')
    at ProductList (app.js:45:23)
    at renderWithHooks ...

Tips 4: ドキュメントを書いてもらう

> このコードの README.md を書いてください。
  インストール方法、使い方、API リファレンスを含めてください。

> JSDoc コメントを全ての関数に追加してください。

Tips 5: テストを自動生成

> utils.js のユニットテストを Jest で書いてください。
  エッジケース（空文字列、null、大きい数値）も含めてください。

Tips 6: リファクタリング

> app.js をリファクタリングしてください：
  - 1 関数 1 責任の原則に従う
  - マジックナンバーを定数に置き換える
  - 同じ処理は共通化する
  - 処理の意図がわかるコメントを追加する

Tips 7: Plan Mode で「設計してから実装」する

複雑なタスクや複数ファイルにまたがる変更は、いきなり実装させず Plan Mode を使いましょう。Claude Code は Explore サブエージェントでリポジトリを調査し、関連ファイル・パターンを要約した実装計画を提示します。計画を承認してから実装に進むことで、手戻りが激減します。

> /plan ユーザー認証機能を追加したい。まず実装計画を立てて。
  （計画を確認・承認してから実装フェーズへ進む）

画面でPlan Modeへの切り替わりを確認します。

Tips 8: 調査はサブエージェントに任せて本筋を汚さない

「多数のファイルを読む」「特定の使われ方を探す」といった調査は、サブエージェントに委譲すると別コンテキストで実行され、メインの会話がログで埋まりません。結論だけが返ってくるので、実装に集中できます。

> サブエージェントを使って、この関数がどこから呼ばれているか調査して。

Tips 9: 繰り返す作業は Skills 化する

デプロイ手順・テスト実行・リリースノート作成など、繰り返すワークフローは .claude/skills/ に Skill（手順書 Markdown） として登録できます。リクエストが Skill の説明に一致したときだけ自動で読み込まれるため、毎回説明する手間が省け、チームで手順を統一できます。まずは Skill から始め、確実な強制が要る場面は Hooks、並列・文脈分離が要る場面はサブエージェントを使い分けるのが定石です。

Tips 10: 生成直後に /simplify でもう一押し

AI が生成したコードには、冗長な記述や見落とした最適化が紛れがちです。まとまったコードを書かせたら、すかさず /simplify を実行して2パス目のレビューをかけると、品質がもう一段上がります。長くなった会話は /compact、コスト確認は /cost も併用しましょう。
