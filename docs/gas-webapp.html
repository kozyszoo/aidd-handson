Web アプリ編

🌐 生成AI活用コーディングハンズオン
～ Google Apps Script (GAS) で Web アプリを作る ～

ここまでは「決まった時間に動いて、こちらへ通知が来る」アプリでした。今度は自分の URL を持つ画面を作ります。ブラウザで開けて、人に渡せるものになります。

前提: 初級編・発展編のタスク通知アプリが動いていること（新しく作っても進められます）

🙋 みなさんの進捗状況を知りたいので、うまく進んでいる場合も、進んでいない場合も絵文字リアクションを積極的に返してください！進んでないよ、というときも遠慮なく！

はじめに

初級編と発展編で作ったアプリには、画面がありませんでした。動くのは決まった時間で、結果はメールやチャットに届く。こちらから何かを見たり、その場で操作したりはできません。

この Web アプリ編では、ブラウザで開ける URL を作ります。作った URL は人に渡せます。渡した相手は、GAS を知らなくても、スプレッドシートを開かなくても使えます。ここが今までとの一番の違いです。

🎯 この編のゴール

  • GAS だけでブラウザから開ける画面を作れるようになる
  • 画面から入力して、スプレッドシートへ書き込めるようにする
  • 誰がその URL を使えるのかを自分で決められるようになる
  • 直したものを公開中の URL へ反映する手順を身につける
🧭 この編で作るもの
Stepできるようになること
1. 一番小さい Web アプリ文字が 1 行だけ出る URL を公開する
2. 見た目を HTML で作るスクリプトと見た目のファイルを分ける
3. シートの中身を表示今日のタスクを一覧で見られるようにする
4. ブラウザから書き込む画面から入力してシートへ 1 行足す
5. 誰が使えるかを決める自分だけ / 全員 の違いを理解して選ぶ
6. 直したら反映するコードの変更を公開中の URL へ反映する
ℹ️ 初級編・発展編をやっていなくても進められます。 Step 3 でタスクのスプレッドシートを使いますが、列が「タスク名 / 日付 / 優先度 / 状態」の並びになっていれば、その場で新しく作ったものでも構いません。

🚪 最初の一歩

Step 1: 一番小さい Web アプリを公開する

いきなり作り込まず、文字が 1 行出るだけのものを先に公開します。「自分の URL が持てた」ことを最初に確かめておくと、この後で詰まったときにどこが悪いのかを切り分けやすくなります。

GAS の Web アプリには、覚えることがひとつだけあります。doGet という名前の関数です。その URL がブラウザで開かれたとき、GAS はこの関数を探して実行します。名前が決まっているので、別の名前では動きません。

🌐 URL を開いてから画面が出るまで
🤖 Gemini にこう聞く
GAS で、ブラウザで開くと「こんにちは」とだけ表示される一番簡単な Web アプリのコードを書いて
💡 うまくいかないとき / 答え合わせ用のコードを見る

既存のコードはそのまま残し、いちばん下に次の関数を追加してください。貼り付けたら 💾（保存）を押すか、Ctrl + S / Cmd + S で保存します。

// ブラウザでこの URL が開かれたときに呼ばれる関数
function doGet() {
  return HtmlService.createHtmlOutput('こんにちは');
}

HtmlService.createHtmlOutput() は「これをブラウザに表示してください」と GAS に渡す書き方です。返さないと何も表示されません。return を書き忘れるとエラーになるので気をつけてください。

📋 公開する手順

  1. GAS の画面右上「デプロイ」→「新しいデプロイ」
  2. 左の「⚙️ 種類の選択」→「ウェブアプリ」を選ぶ
  3. 「次のユーザーとして実行」→ 自分（そのままで OK）
  4. 「アクセスできるユーザー」→ 自分のみ（ここは Step 5 で詳しく扱います）
  5. 「デプロイ」を押す → アクセスを承認する
  6. 表示された ウェブアプリの URL をコピーして、ブラウザで開く
⚠️ 初めて公開するときは、承認の画面が 2 つ出ます。
  1. 「REVIEW PERMISSIONS」を押す（英語のままです）
  2. 「このアプリは Google によって確認されていないため…」という黄色い枠が出ます。自分が書いたスクリプトなので、そのまま進めて構いません
  3. 下までスクロールして「許可」を押す

1 つ目は英語の小さなダイアログで、アプリ名の横に (Unverified) と赤字で出ます。ボタンは「REVIEW PERMISSIONS」の 1 つだけです。これを押すと、次の日本語の画面へ進みます。

💡 ブラウザに「こんにちは」と表示されれば、Web アプリの公開は成功です。Step 2 へ進んでください。

🎨 見た目を作る

Step 2: 見た目を HTML のファイルに分ける

Step 1 では、表示する文字をスクリプトの中に直接書きました。見出しや入力欄が増えると、スクリプトの中に文字列として HTML を書く形では管理しにくくなります。

そこで、見た目は見た目で別のファイルに分けます。 GAS のスクリプト（.gs）と、画面（.html）を別々に置いて、スクリプトから呼び出す形にします。

🗂️ コードと見た目を分けてつなぐ
🤖 Gemini にこう聞く
GAS の Web アプリで、画面の HTML を別ファイルに分けて表示する形に書き換えて。HtmlService.createTemplateFromFile を使って

📋 準備

  1. GAS の画面左「ファイル」の ＋ → HTML を選ぶ
  2. 名前を index にする（.html は自動で付きます）
💡 うまくいかないとき / 答え合わせ用のコードを見る

まず index.html の中身です。ふつうの HTML がそのまま書けます。

<!DOCTYPE html>
<html>
  <head>
    <base target="_top">
    <style>
      body { font-family: sans-serif; max-width: 640px; margin: 40px auto; padding: 0 16px; }
      h1 { font-size: 1.4rem; }
    </style>
  </head>
  <body>
    <h1>今日のタスク</h1>
    <p>ここに一覧を出します</p>
  </body>
</html>

次に コード.gs のほうを、この HTML を読み込む形に書き換えます。

function doGet() {
  // 'index' は作った HTML ファイルの名前（.html は書かない）
  return HtmlService.createTemplateFromFile('index').evaluate();
}
ℹ️ <base target="_top"> は消さないでください。 GAS の Web アプリは、内側にもう 1 枚画面がはめ込まれた形で表示されます。この 1 行が無いと、ページ内のリンクを押したときにその小さい枠の中で開いてしまい、表示が崩れます。

📄 読み取り

Step 3: スプレッドシートの中身を画面に出す

スプレッドシートに入っているタスクを読み、画面に一覧で表示します。

スクリプト側でタスクを配列として読み、HTML 側で条件分岐とループを使って表示します。

📄 シートのデータが画面になるまで
🤖 Gemini にこう聞く
GAS の Web アプリで、スプレッドシートのタスク一覧を読んで画面にリストで表示するようにして。シートの列は「タスク名 / 日付 / 優先度 / 状態」の並び
💡 うまくいかないとき / 答え合わせ用のコードを見る

スクリプト側でタスクを読み、配列のままテンプレートへ渡します。

// 自分のシート名に置き換える（初級編で控えたもの。既定は「シート1」）
const SHEET_NAME = 'シート1';

function doGet() {
  const template = HtmlService.createTemplateFromFile('index');
  template.tasks = getTasks();
  return template.evaluate().setTitle('今日のタスク');
}

// 未完了のタスクだけを配列で返す
function getTasks() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName(SHEET_NAME);
  const rows = sheet.getDataRange().getValues();
  return rows.slice(1).filter(row => row[3] !== '完了'); // 1 行目は見出しなので除く
}

HTML 側では、渡ってきた配列をループして 1 件ずつ表示します。Step 2 で作った <base target="_top"> と CSS を含む完全な形です。

<!DOCTYPE html>
<html>
  <head>
    <base target="_top">
    <style>
      body { font-family: sans-serif; max-width: 640px; margin: 40px auto; padding: 0 16px; }
      h1 { font-size: 1.4rem; }
    </style>
  </head>
  <body>
    <h1>今日のタスク</h1>
    <? if (tasks.length === 0) { ?>
      <p>未完了のタスクはありません</p>
    <? } else { ?>
      <ul>
        <? for (let i = 0; i < tasks.length; i++) { ?>
          <li><?= tasks[i][0] ?>（<?= tasks[i][2] ?>）</li>
        <? } ?>
      </ul>
    <? } ?>
  </body>
</html>
ℹ️ テンプレート内の 3 つの書き方を区別します。 <? ?> は値を出力せず、条件分岐やループに使います。<?= ?> は値を HTML エスケープして出力するため、人が入力したタスク名の表示に使います。<?!= ?> は HTML としてそのまま出力するため、人が入力した値には使いません。
⚠️ 置き換える場所はコード先頭の const SHEET_NAME = 'シート1'; です。 'シート1' を、初級編で控えた画面下のタブ名（シート1 または Sheet1 など）に置き換えてください。シート名が一致しないと画面を表示できません。
💡 こうなれば成功です。 未完了のタスクだけが一覧に出ます。「完了」と書いた行は出てきません。
💡 保存したコードは「デプロイをテスト」で確認できます。 「デプロイ」→「デプロイをテスト」でテスト用 URL を開くと、正式なデプロイを更新せずに最新のコードを確認できます。公開用 URL へ反映する手順は Step 6 で扱います。

✍️ 書き込み

Step 4: 画面から入力してシートへ書き込む

画面に入力欄とボタンを置いて、ブラウザからスプレッドシートへタスクを追加できるようにします。

新しく出てくるのは google.script.run というひとつの書き方だけです。画面の側から、GAS の関数を名指しで呼ぶための仕組みです。

🔄 ブラウザと GAS の非同期の往復
🤖 Gemini にこう聞く
この Web アプリに入力欄とボタンを足して、押したらスプレッドシートへタスクを 1 行追加するようにして。google.script.run を使って
💡 うまくいかないとき / 答え合わせ用のコードを見る

コード.gs の末尾に、次の関数を追加します（doGet と getTasks、先頭の SHEET_NAME はそのまま残します）。

// 画面から呼ばれて、シートへ 1 行足す関数
function addTask(taskName) {
  // 空のまま送られてきたら、何もせず終わる
  if (!taskName) return '入力してください';

  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName(SHEET_NAME);
  const today = Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyy/MM/dd');

  sheet.appendRow([taskName, today, '中', '未完了']);

  return '追加しました';
}

次に index.html を、入力欄とボタンを含む次の完全なコードに置き換えます。

<!DOCTYPE html>
<html>
  <head>
    <base target="_top">
    <style>
      body { font-family: sans-serif; max-width: 640px; margin: 40px auto; padding: 0 16px; }
      h1 { font-size: 1.4rem; }
    </style>
  </head>
  <body>
    <h1>今日のタスク</h1>
    <? if (tasks.length === 0) { ?>
      <p>未完了のタスクはありません</p>
    <? } else { ?>
      <ul>
        <? for (let i = 0; i < tasks.length; i++) { ?>
          <li><?= tasks[i][0] ?>（<?= tasks[i][2] ?>）</li>
        <? } ?>
      </ul>
    <? } ?>

    <h2>タスクを追加</h2>
    <input type="text" id="taskName" placeholder="やることを入力">
    <button onclick="send()">追加</button>
    <p id="message"></p>

    <script>
      function send() {
        const name = document.getElementById('taskName').value;

        google.script.run
          .withSuccessHandler(onSuccess)  // 成功したらこれを呼ぶ
          .withFailureHandler(onFailure)  // 失敗したらこれを呼ぶ
          .addTask(name);                 // GAS 側の関数名をそのまま書く

        document.getElementById('message').textContent = '送信中...';
      }

      function onSuccess(result) {
        document.getElementById('message').textContent = result;
        document.getElementById('taskName').value = ''; // 入力欄を空に戻す
      }

      function onFailure(error) {
        document.getElementById('message').textContent = 'エラー: ' + error.message;
      }
    </script>
  </body>
</html>
ℹ️ すぐには返ってきません。 google.script.run は、頼んだらその場で次へ進みます。結果はあとからwithSuccessHandler に渡した関数へ届きます。だから「送信中...」を先に出しておいて、返ってきたら書き換える、という順番になります。
ℹ️ 画面の一覧はブラウザを再読み込みすると更新されます。 「追加しました」と表示された時点で、シートにはタスクが追加されています。
💡 withFailureHandler を必ず書いてください。 これが無いと、失敗したとき画面には何も起きません。押しても反応しないように見えて、原因がまったく分からなくなります。発展編の Step 8 と同じ考え方です。
💡 こうなれば成功です。 入力して「追加」を押すと「追加しました」と出ます。ブラウザを再読み込みすると、一覧にも増えています。

ブラウザを再読み込みすると、追加したタスクが一覧にも並びます。

Step 5: 誰がこの URL を使えるのかを決める

画面ができたので、人に渡せる状態になりました。ここで必ず決めておかないといけないことがあります。

デプロイのときに出てくる 2 つの選択肢です。見落としやすいのですが、この 2 つの組み合わせで、アプリの性格が変わります。

🔐 「実行する人」×「開ける人」の 2 軸
⚙️ デプロイの 2 つの設定
設定意味
次のユーザーとして実行誰の権限で動くか。「自分」にすると、他の人が使ってもあなたのスプレッドシートを読み書きします
アクセスできるユーザー誰がこの URL を開けるか。「自分のみ」「Google アカウントを持つ全員」などから選びます

📋 よく使う組み合わせ

  • 自分専用のツールにする
    実行 = 自分 ／ アクセス = 自分のみ
    練習中はこれで十分です。Step 1 で選んだのもこれです。
  • チームに使ってもらう（シートは自分のものを共有）
    実行 = 自分 ／ アクセス = 全員
    相手はシートの権限を持っていなくても使えます。あなたの権限で動くためです。
⚠️ 「実行 = 自分」＋「アクセス = 全員」は、便利な代わりに強い設定です。 URL を知っている人は誰でも、あなたの権限でシートを書き換えられることになります。中身を消す処理を書いていれば、それも実行できてしまいます。人に渡すときは、渡す相手を選べる形（アクセス = 自分の組織内、など）から試してください。
💡 URL は推測できない長さですが、パスワードではありません。 転送されれば、その先の人も開けます。発展編 Step 7 の Webhook と同じ考え方で、渡した先から広がりうるものとして扱ってください。

🔄 更新する

Step 6: 直したものを公開中の URL へ反映する

コードを直して保存しても、公開中の URL にはすぐには反映されません。反映にはデプロイの更新操作が必要です。

🚀 保存とデプロイは別の操作

📋 反映のしかた

  1. 「デプロイ」→「デプロイを管理」
  2. 右上の鉛筆マーク（編集）を押す
  3. 「バージョン」を「新バージョン」に変える
  4. 「デプロイ」を押す
ℹ️ URL は変わりません。 この手順で更新するかぎり、渡した相手のリンクはそのまま使えます。一方「新しいデプロイ」を選ぶと別の URL が新しくできます。人に渡したあとでこれをやると、相手は古い画面を見続けることになるので注意してください。
💡 直しながら試すときは、テスト用の URL が使えます。 「デプロイ」→「デプロイをテスト」で開く URL は、保存した最新のコードがそのまま動きます。毎回デプロイし直さずに確認できるので、作っている間はこちらが速いです。人に渡すときだけ、上の手順で正式に反映してください。
